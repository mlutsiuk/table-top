# Статуси кампанії

## Стани

```
DRAFT → ACTIVE → ARCHIVED
```

| Статус | Що можна робити |
|---|---|
| `DRAFT` | Повне редагування: механіки, Assets, формули, налаштування |
| `ACTIVE` | Механіки заблоковані. Гра йде. Entity створюються/видаляються. |
| `ARCHIVED` | Тільки читання. |

---

## ⚠️ Статуси ігноруються на перших етапах

**Рішення:** Логіка блокування і pre-flight check **не реалізується до Етапу 4**.

**Чому:** Блокування залежить від повністю реалізованої системи механік, формул і валідації. Реалізовувати це до самих механік — передчасна оптимізація.

Поле `status` в БД є і має тип `CampaignStatus` enum. Але логіка яка реагує на статус — додається в Етапі 4.

---

## Перехід DRAFT → ACTIVE (Етап 4+)

Явна дія майстра ("Запустити кампанію"). В момент переходу — pre-flight check:

```
Перевіряємо:
✓ Всі MechanicInstances мають валідний конфіг (Zod + бізнес-логіка)
✓ Немає broken посилань у формулах (поля не видалені і не перейменовані)
✓ Немає циклічних залежностей в графі формул

Показуємо попередження:
⚠ Після переходу конфіг механік буде заблоковано
⚠ Для змін треба буде перейти назад в DRAFT (якщо підтримуємо)
```

---

## Зміни конфігу в DRAFT

**Безпечні** (без попередження):
- Додати нове поле
- Змінити `label`
- Змінити `default` value

**Деструктивні** (показуємо попередження + вимагаємо підтвердження):
- Видалити поле → може зламати формули і Actions які посилаються на нього
- Перейменувати `key` поля → аналогічно
- Змінити `type` поля → несумісні дані в AssetTrait/EntityTrait

---

## В статусі ACTIVE

Конфіг MechanicInstance заблокований повністю. Можна:
- Створювати/видаляти Entity
- Змінювати EntityTrait (dynamic поля)
- Запускати Actions
- Додавати/видаляти ефекти
