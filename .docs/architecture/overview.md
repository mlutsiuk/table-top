# Огляд архітектури TableTop Engine

## Місія

TableTop Engine — VTT (Virtual Tabletop) система де **ігрова логіка не зашита в код, а інтерпретується на основі даних наданих користувачем**.

**Проблема існуючих рішень:**
- Roll20, Foundry VTT — або прив'язані до D&D, або вимагають від користувача писати JavaScript.
- Foundry вирішує кастомізацію через JS модулі — але це не для звичайних майстрів.

**Рішення TableTop:**
- Система надає абстрактні інструменти ("контейнери") які майстер наповнює через UI.
- Система не "знає" що таке "Сила" чи "Хіти" поки майстер не створить відповідну механіку.
- Гнучкість рівня розробника — доступна без знання програмування.

**Аналогія з Terraform:**
```
Terraform        →  TableTop Engine
Provider         →  Mechanic (код, логіка)
Resource         →  MechanicInstance (конфіг під кампанію)
Variable         →  Field (static/dynamic)
Output           →  Formula field
State file       →  AssetTrait / EntityTrait
Plan (dry run)   →  pre-flight check при DRAFT→ACTIVE
Dependency graph →  FieldReference таблиця (відкладено)
```

**Поточний фокус:**
- Solo Master Tool — спочатку без multiplayer
- DOM замість Canvas — верифікуємо архітектуру даних без складності рендерингу
- Canvas/PixiJS — додаткове View яке підключається в Етапі 6

## Технологічний стек

| Технологія | Причина |
|---|---|
| **Nuxt.js** | Fullstack framework, спільна логіка (Zod) на клієнті і сервері, SSR |
| **PostgreSQL** | JSONB для поліморфних трейтів, транзакційність, повнотекстовий пошук |
| **Prisma ORM** | Type-safety для складних реляційних зв'язків |
| **tRPC** | Пряма передача типів від БД до фронтенду, Zod валідація |
| **Zod** | Runtime валідація схем, спільна між клієнтом і сервером |
| **Tailwind CSS** | Гнучкість для Sheet Builder |
| **Uploadthing** | Завантаження файлів (капотом AWS S3), офіційний Nuxt модуль |
| **WebSockets** | Real-time синхронізація (Етап 4+) |
| **TipTap** | Вікі-редактор для Asset опису |

**Авторизація:** JWT токени через Google OAuth (вже реалізовано).

## Рівні системи

```
┌─────────────────────────────────────────────────┐
│  ENGINE LEVEL (код розробника, незмінний)       │
│  Asset / Entity / AssetTrait / EntityTrait      │
│  EntityRelation API                             │
│  Layered State Resolve                          │
│  Formula Parser                                 │
│  Action Engine                                  │
│  MechanicRegistry                               │
└─────────────────────────────────────────────────┘
            ↕ використовують
┌─────────────────────────────────────────────────┐
│  MECHANIC LEVEL (код розробника)                │
│  values-v1, sheet-v1, effects-v1               │
│  Реєструються в MechanicRegistry               │
│  Надають: schemas, components, methods, hooks   │
└─────────────────────────────────────────────────┘
            ↕ налаштовується через
┌─────────────────────────────────────────────────┐
│  CAMPAIGN LEVEL (налаштування майстра через UI) │
│  MechanicInstance (які механіки підключені)     │
│  Конфіг інстансів (поля, формули)              │
│  Assets і їх AssetTraits                        │
│  Actions на Assets                              │
└─────────────────────────────────────────────────┘
            ↕ виконується як
┌─────────────────────────────────────────────────┐
│  RUNTIME LEVEL (під час гри)                    │
│  Entity (інстанси Assets)                       │
│  EntityTrait (поточний стан)                    │
│  EntityRelation (інвентар, ефекти, зв'язки)    │
│  SceneEntity (позиції на сцені — відкладено)    │
└─────────────────────────────────────────────────┘
```

### Що на якому рівні живе

| Рівень | Хто створює | Приклад |
|---|---|---|
| Engine | Розробник (код) | Логіка Layered State Resolve |
| Mechanic | Розробник (код) | `values-v1` механіка |
| Campaign | Майстер (UI) | MechanicInstance "health" з полями max_hp, hp |
| Runtime | Система/Гра | Entity "Goblin #3" з hp=2 |

## Механіки двигуна (фінальний список)

На рівні двигуна є рівно три механіки:

| Механіка | Призначення |
|---|---|
| `values-v1` | Зберігання значень: числа, рядки, bool, формули. Покриває ~80% потреб RPG. |
| `sheet-v1` | Шаблон листа персонажа як дерево нод. Тільки відображення, не зберігає дані. |
| `effects-v1` | Активні ефекти що модифікують values через EntityRelation. |

Все інше (інвентар, спорядження, союзники) — це EntityRelation з різними `key`, а не окремі механіки.
